# 이삐댕이의 뽀뽀공원

꽃 사이에 나타나는 이삐를 터치해 댕이의 뽀뽀를 전하는 모바일 웹 미니게임입니다. TypeScript + Phaser 3 + Vite, 서버와 API 키 없이 정적 파일만으로 실행합니다.

## 실행

Node.js 22.12 이상을 사용하세요.

```sh
npm ci
npm run dev
```

터미널에 표시되는 `http://localhost:5173/game/`를 엽니다. 같은 Wi-Fi의 휴대폰에서는 터미널의 Network 주소 뒤 `/game/`로 접속합니다. 방화벽이 허용되어야 합니다.

```sh
npm test          # 게임 규칙 단위 테스트
npm run build    # TypeScript 검사 + 프로덕션 빌드
npm run preview  # dist 정적 미리보기
```

## 규칙

- 총 3라운드, 라운드마다 찾기 기회 10번. 이삐는 매 기회 반드시 한 곳에 나타납니다.
- 이삐 터치 +1, 방해 꽃 터치 −2, 꽃밭의 빈 공간 터치 −1. 점수는 음수가 될 수 있습니다.
- 한 번 누르면 해당 기회 종료. 시간 안에 누르지 못하면 0점으로 기회를 소모합니다.
- 한 기회에 여러 번 눌러도 한 번만 판정합니다. HUD와 하단 문구는 점수 판정 영역에서 제외합니다.
- 라운드 점수 7점 이상이면 통과. 각 라운드 점수는 초기화됩니다.
- 노출 시간 3.0 → 2.2 → 1.6초, 방해 꽃은 2 → 3 → 4개로 증가합니다.
- 실패하면 게임 종료, 다시 시작은 1라운드부터. 최고기록은 완료한 라운드들의 누적 점수(최대 30점)를 저장합니다.
- 배경으로 이동하거나 화면 방향이 바뀌면 일시정지합니다. 가로에서도 세로형 게임 보드를 유지합니다.
- 소리는 기본 ON, 최초 시작 버튼 또는 소리 버튼 터치 후 활성화합니다. Web Audio 합성 배경음과 효과음으로 별도 음원 파일은 없습니다.

## 구조와 수정

- `src/logic.ts`: 점수, 라운드, 노출 시간, 최고기록
- `src/main.ts`: Phaser Canvas 장면, UI 전환, 터치 판정, 모션
- `src/audio.ts`: 직접 작곡한 합성 멜로디와 효과음
- `src/style.css`: 반응형 UI, Safe Area, 결과 애니메이션
- `public/img/`: 실제 게임이 불러오는 독립 WebP 이미지
- `source/`: 제공받은 원본 캐릭터와 글씨 참고 이미지
- `art-source/`: 생성 원본 및 원본 글꼴 보관
- `ASSET-PROMPTS.md`: 이미지 생성 프롬프트와 에셋 제작 방식
- `tests/`: 규칙 테스트 및 Playwright 사용자 흐름 테스트

Phaser의 입력·트윈·장면 관리가 이번 게임의 애니메이션 요구에 적합해 엔진을 사용했습니다. 간단한 Canvas 직접 구현도 가능하지만 별도 애니메이션 수명 관리가 필요합니다. 모션은 생성한 일러스트에 Phaser 트윈과 CSS, 하트·꽃잎 파티클을 합성한 실시간 연출입니다. 동영상 파일은 아닙니다.

레티나에서는 렌더 해상도를 최대 2배로 올리고, 이미지 WebP 압축, 짧은 파티클 수명, 최대 12개 배경 꽃잎, 최초 로드 후 에셋 재사용으로 비용을 제한합니다. OS의 동작 줄이기 설정에서는 반복 모션과 꽃잎을 줄입니다.

`?debug`를 붙이면 FPS, 로드 이후 경과 시간, 텍스처 수, 장면 오브젝트 수가 표시됩니다. 실제 로딩 시간과 전송량은 브라우저 개발자 도구 Network에서 확인합니다. `?test`는 브라우저 자동화용 읽기 전용 상태 스냅샷을 제공합니다.

글꼴은 Jua를 사용하며 게임에 쓰이는 글자만 WOFF로 포함했습니다. 문구를 추가하면 `scripts/subset-font.py`로 서브셋을 갱신하세요. 제목은 `letter.jpg`의 느낌을 참고해 새로 생성한 이미지이며 원본의 실제 폰트 파일을 추출한 것이 아닙니다.

## GitHub Pages

대상 저장소: https://github.com/k220volt/game

서비스 주소: https://k220volt.github.io/game/

`vite.config.ts`의 `base: '/game/'`가 저장소 경로를 처리합니다. 다른 저장소에 옮기면 해당 값을 바꾸세요. 이미지 주소는 Vite base를 따릅니다.

`.github/workflows/deploy.yml`은 main push 시 설치 → 단위 테스트 → 타입 검사/빌드 → Pages 배포를 수행합니다. 현재 저장소는 **Settings → Pages → Build and deployment → Source: GitHub Actions**로 설정했습니다. 저장소를 복제해 새로 배포할 때에도 같은 설정을 선택하세요. 환경 보호 규칙이 있으면 github-pages 배포를 허용해야 합니다. 비밀 API 키나 서버 설정은 필요 없습니다.

자동 배포 권한이 부족해도 `dist/`에 완성된 배포 파일이 남습니다. 파일을 직접 더블클릭하지 말고 HTTP 정적 서버에서 서비스하세요. `deployment.zip`은 dist 내용을 담은 로컬 배포용 압축본입니다.

## 브라우저 테스트

설치된 Google Chrome을 사용하는 Playwright 테스트입니다. 서버를 먼저 실행합니다.

```sh
npm run dev -- --port 5174
npm run test:e2e
```

테스트는 3라운드 터치 완주, 클리어/실패, 최고기록, 재시작, 마우스 입력, 중복 입력, 감점, 시간 초과, 일시정지, 소리 버튼, 320×568 / 375×667 / 390×844 / 430×932 / 768×1024 / 844×390 레이아웃을 검사합니다. 스크린샷은 `test-results/`에 저장됩니다.

실제 iPhone Safari와 Android Chrome 기기에서의 터치 감각, 오디오 출력, 노치/홈 인디케이터, 저사양 기기의 60FPS는 별도 실기기 확인이 필요합니다. Chrome 모바일 에뮬레이션을 실기기 테스트로 간주하지 않습니다. 상세 결과는 `TEST-RESULTS.md`에 기록합니다.
